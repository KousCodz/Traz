      TECHNICAL NOTES / 04

      Methodology

      TRACE presents multiple comparison measures and matching content so users can inspect the evidence behind a result.

      How TRACE works

      TRACE compares two user-provided inputs using text analysis or source-code analysis. The implemented methods are Rabin-Karp string matching and Longest Common Subsequence (LCS) using dynamic programming.

      1. Document comparison

      TRACE extracts text from supported PDF, DOCX and TXT files. Users can also paste text directly. The extracted or pasted text is tokenized for comparison. Matching sequences and LCS results help users inspect overlapping content.

      2. Source-code comparison

      TRACE compares uploaded source files or pasted code snippets. Tokenization and the comparison behavior depend on the backend implementation. Results may include matching code sequences, LCS information and line-by-line differences.

      3. Rabin-Karp string matching

      Rabin-Karp uses hashing to identify candidate matches between sequences. Candidate matches can then be checked against actual tokens. It is useful for finding exact contiguous sequences.

      4. Longest Common Subsequence

      The Longest Common Subsequence is the longest sequence of tokens that occurs in both inputs in the same relative order. Matching tokens do not need to be adjacent. Dynamic programming computes the result by solving smaller subsequence problems.

      LCS complements Rabin-Karp: Rabin-Karp identifies contiguous matches, while LCS can identify common tokens even when other tokens occur between them.

      5. Understanding the scores

      The Rabin-Karp score represents matching-token coverage according to the implemented method. The LCS score represents similarity according to the backend's LCS formula. Overall similarity uses the combination implemented in the backend. These are project-specific measures, not standardized plagiarism scores.

      If LCS is unavailable because of backend limits, it should be reported as unavailable rather than treated as zero.

      6. Scope and limitations

      TRACE compares only content supplied by the user. It does not search the internet or external plagiarism databases. Results depend on text extraction, tokenization, algorithms and backend limits. Similarity alone does not prove plagiarism.

      PROJECT NOTES / 06

      About TRACE

      A document and source-code similarity analyser built to make comparisons easier to inspect and understand.

      Purpose

      TRACE helps users compare two documents or two source-code inputs, review overlapping content and inspect differences in context.

      Designed around evidence

      Instead of treating a similarity percentage as a final judgement, TRACE presents matching passages or code sequences to help users make an informed review.

      Scope and limitations

      TRACE compares user-provided content and does not search external plagiarism databases. Results depend on supported file formats and implemented comparison methods. Similarity alone does not prove plagiarism.
